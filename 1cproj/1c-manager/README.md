# Менеджер 1С (графическая панель)

Локальная веб-панель для управления контейнерами 1С. Нужен только Python 3, внешние пакеты не требуются.

## Запуск

    ./gui.sh                      # из папки, где лежат 1c-server, 1c-client и 1c-manager
    ./gui.sh --port 9000          # другой порт
    ./gui.sh --server-dir /путь/1c-server --client-dir /путь/1c-client

В консоли появится ссылка вида http://127.0.0.1:8765/?token=...; браузер откроется сам.
Токен меняется при каждом запуске. Остановка: Ctrl+C.

## Права на docker

Панель выполняет docker без пароля. Добавьте пользователя в группу docker и перезайдите в систему:

    sudo usermod -aG docker $USER

(Подойдёт и sudo без пароля для docker: тогда панель использует `sudo -n docker`.)

## Возможности

- Контейнеры: состояние, старт/стоп/рестарт, логи, запуск и остановка сервера целиком.
- Память сервера 1С: текущий лимит и фактический расход (docker stats), изменение лимита. Значение хранится в `1c-server/.env` (`SERVER_MEMORY_LIMIT`) и применяется пересозданием контейнера `onec-server` — сервер перезапускается, сеансы завершаются. `0` — без лимита.
- Базы 1С: список, создание, удаление (с базой PostgreSQL или без), выгрузка в .dt, загрузка .dt с восстановлением базы, загрузка .cf с обновлением конфигурации, сеансы и их завершение.
- Загрузка .dt/.cf через вкладку «Базы 1С»: веб-панель атомарно сохраняет файл в BACKUP_DIR/dt или BACKUP_DIR/cf на хосте (старый файл не повреждается при обрыве загрузки), затем import.sh копирует его командой docker cp в onec-server и проверяет точное совпадение размера; максимальный размер — 8 ГБ. Для .dt данные выбранной базы заменяются, перед восстановлением завершите сеансы пользователей.
- Импорт выполняет `ibcmd` (платформа 8.3.20+): `.dt` — `ibcmd infobase restore --force` напрямую в PostgreSQL, без конфигуратора и Xvfb. Для `.cf` — `ibcmd infobase config load` + `config apply`; если платформа отказывает (кластерная база), скрипт автоматически повторяет через конфигуратор.
- В форме импорта есть поля «Пользователь PostgreSQL» и «Пароль PostgreSQL»: они нужны `ibcmd` для подключения к СУБД. Пустые поля — берутся `POSTGRES_USER`/`POSTGRES_PASSWORD` из `1c-server/.env`.
- PostgreSQL: список баз с размерами, дамп.
- Выгрузки: дерево файлов из BACKUP_DIR (сервер) и EXPORT_DIR (клиент), включая вложенные папки dt/cf, со скачиванием.
- Клиент и лицензии: запуск клиента 1С, перенос полученных лицензий, файлы лицензий на сервере.
- Сборка: build.sh для сервера и клиента с выводом в консоль панели. По кнопке «Собрать образы сервера» открывается окно: выбор папок с установщиками (1С и PostgreSQL) и память сервера; найденные `.run`/`.deb` загружаются в `server/dist` и `postgres/dist` (файлы того же размера не передаются), затем идёт сборка.

## Безопасность

Панель слушает только 127.0.0.1, требует токен, проверяет заголовок Host и выполняет лишь заранее заданные
действия (произвольные команды запустить нельзя). Скачивать можно только файлы из каталогов выгрузок.
Пароль 1С при выгрузке .dt передаётся скрипту аргументом, поэтому кратко виден в списке процессов этого
компьютера. Не открывайте панель наружу (не пробрасывайте порт).

## Если задача не запускается

Результат каждой кнопки виден в консоли внизу страницы (рамка зелёная при успехе, красная при ошибке).
Клиентский контейнер и сервер запускаются через скрипты проектов (`client.sh up`, `start.sh`), поэтому
ошибки такие же, как в терминале: например, пустой SERVER_IP в 1c-client/.env или не собранный образ.
Ту же команду можно выполнить вручную: `cd 1c-client && ./client.sh up`.

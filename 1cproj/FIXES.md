## Если 1С пишет «Unable to initialize GTK+»

Это значит, что `1cv8` не получил рабочий X-дисплей. Проверка обёртки в контейнере:

```bash
docker compose exec -T onec-server /usr/local/bin/1c-xvfb sh -c 'echo DISPLAY=$DISPLAY; ls -l /tmp/.X11-unix'
```

Должно напечатать `DISPLAY=:99` и сокет `X99`. Если обёртка падает — она печатает журнал
Xvfb; там будет причина (нет `/tmp/.X11-unix`, нет прав, битый пакет xvfb).
Образы нужно пересобрать: сервер — для импорта/выгрузки .dt, клиент — для `export-db.sh`.

## Как собрать у себя

### Сервер (машина с 1С и PostgreSQL)

```bash
cd 1c-server
# 1) .env: ONEC_VERSION, POSTGRES_PASSWORD, POSTGRES_BASE_IMAGE (дистрибутив ваших deb)
# 2) postgres/dist — все deb PostgreSQL для 1С
# 3) server/dist — setup-full-<версия>-x86_64.run
chmod +x *.sh
./build.sh
./start.sh
```

### Клиент

```bash
cd 1c-client
# 1) .env: SERVER_IP, ONEC_VERSION, NETHASP_ADDRS, CLIENT_UID=$(id -u)
# 2) dist/setup-full-<версия>-x86_64.run
chmod +x *.sh
./build.sh
./client.sh check
```

Если сборка postgres упадёт на зависимостях — почти всегда `POSTGRES_BASE_IMAGE` не совпадает
с дистрибутивом deb-пакетов 1С. Посмотрите, что требуют пакеты:

```bash
dpkg-deb -f postgresql-*.deb Depends
# libc6 (>= 2.43), libicu78, libxml2-16  -> ubuntu:26.04
# libc6 (>= 2.39), libicu74              -> ubuntu:24.04
# libc6 (>= 2.35), libicu70              -> ubuntu:22.04
```

Сборка теперь сама проверяет `libc6` и пишет: «deb-пакеты 1С требуют libc6 >= 2.43,
в базовом образе 2.39 — задайте POSTGRES_BASE_IMAGE».

### Если 1С не аутентифицируется в PostgreSQL

`pg_hba.conf` настроен на `md5`, пароль суперпользователя в PostgreSQL 14+ хранится
как SCRAM-SHA-256; клиент 1С 8.5 это поддерживает. Если ваш релиз платформы старее,
в `postgres/entrypoint.sh` перед `initdb` добавьте `-c password_encryption=md5`
и пересоберите образ (том `pg-data` придётся пересоздать: `./reset.sh`).

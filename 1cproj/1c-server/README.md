# 1c-server: PostgreSQL + сервер 1С

1. Скопируйте .env.example в .env и задайте уникальный длинный POSTGRES_PASSWORD.
   Пароль не храните в Git и не оставляйте значение-заглушку из примера.
2. Положите пакеты в postgres/dist (только .deb PostgreSQL для 1С) и server/dist
   (.deb платформы или установщик setup-full-<версия>-x86_64.run). Либо укажите папки
   с этими файлами в веб-панели (вкладка «Сборка») — ./build.sh <папка-1С> <папка-PostgreSQL>
   подставит их в dist/ сам.
3. Версия платформы и базовые образы задаются в .env.

```bash
chmod +x *.sh
./build.sh     # сборка образов (принимает и .deb, и .run)
./start.sh     # запуск, создание базы mybase и docker-сети onec-net
./reset.sh     # удалить данные и начать заново
```

Сервер публикует порты 1540, 1541, 1560-1591 и создаёт сеть onec-net,
к которой подключаются серверные процессы 1С и PostgreSQL.
Порт 1545 (RAS) публикуется только на 127.0.0.1: кластер работает с -seclev 0,
и в сеть его выставлять нельзя.

## Веб-клиент 1С через Apache и HTTPS

Ветка apache добавляет Apache 2.4 в контейнер onec-server. Для публикации
используется штатная утилита webinst из компонента ws платформы 1С.
Порты HTTP 80 и HTTPS 443 проброшены на хост. Конфигурация Apache, публикации
и автоматически созданный самоподписанный сертификат сохраняются в именованном
Docker volume apache-config.

При первом запуске сервер автоматически создаёт самоподписанный сертификат
и перенаправляет запросы с HTTP на HTTPS. Для локальной сети откройте:

    https://IP-СЕРВЕРА/ИМЯ-БАЗЫ

Браузер покажет предупреждение о недоверенном сертификате. Это ожидаемо для
самоподписанного сертификата; для устранения предупреждения установите свой
сертификат от доверенного центра или добавьте собственный CA в доверенные на
клиентских компьютерах.

По умолчанию сертификат содержит SAN для IP 192.168.239.130, 127.0.0.1,
а также имён localhost и onec-server. Если IP сервера другой, задайте в .env
переменную HTTPS_CERT_SAN, например:

    HTTPS_CERT_SAN=IP:192.168.1.50,IP:127.0.0.1,DNS:localhost,DNS:onec-server

Для собственного сертификата положите файлы в каталог certs рядом с docker-compose.yml
(он монтируется в контейнер как /etc/onec-certs), затем задайте в .env:

    HTTPS_CERT_FILE=/etc/onec-certs/fullchain.pem
    HTTPS_KEY_FILE=/etc/onec-certs/privkey.pem

Закрытый ключ не добавляйте в Git. После изменения сертификата пересоздайте контейнер
или перезапустите Apache. Чтобы обновить автоматически созданный сертификат, удалите
только файлы /etc/apache2/ssl/onec.crt и /etc/apache2/ssl/onec.key внутри контейнера
и перезапустите его; Docker volumes с данными 1С удалять не нужно.

После сборки и запуска сервера откройте вкладку «Базы 1С» в менеджере:
- «Опубликовать в браузере» — создаёт публикацию выбранной базы;
- «Снять публикацию» — удаляет её;
- кнопки управления Apache запускают, останавливают или перезапускают веб-сервер.

В образ сервера включён компонент платформы ws; если используется собственная
переменная ONEC_RUN_COMPONENTS в .env, добавьте в неё ws.
После обновления исходников выполните сборку серверного образа и пересоздание контейнера.

Лицензии лежат в ./licenses (монтируются в /var/1C/licenses).
Пароль БД задаётся один раз — POSTGRES_PASSWORD в .env; common.sh берёт его оттуда же,
поэтому DB_PASS вручную задавать не нужно. После первой инициализации тома pg-data
смена POSTGRES_PASSWORD не меняет пароль в базе.

## Сетевой доступ к серверу

Для веб-публикаций откройте HTTP и HTTPS:

    sudo firewall-cmd --permanent --add-port=80/tcp --add-port=443/tcp
    sudo firewall-cmd --reload

Лицензии сервера размещайте в ./licenses и перезапускайте onec-server при необходимости.

## Архитектура: amd64 и arm64

В server/dist и postgres/dist выбираются только пакеты, подходящие архитектуре машины
(amd64 или arm64); у платформы дополнительно проверяется версия ONEC_VERSION
(принимаются оба вида записи: 8.5.1.1522 и 8.5.1-1522).
Платформа ставится в /opt/1cv8/current.

## Установщик .run

Если для версии нет .deb, положите в server/dist установщик setup-full-<версия>-x86_64.run.
По умолчанию ставятся компоненты server,server_admin,client_full,ru (список меняется
переменной ONEC_RUN_COMPONENTS в .env). client_full нужен для выгрузки .dt в контейнере.


## Сетевой ключ HASP (NetHASP)

Адреса менеджеров лицензий лежат в server/nethasp.ini. Файл монтируется в
/opt/1cv8/conf/nethasp.ini (docker-compose.yml), поэтому после правки достаточно
пересоздать контейнер, пересобирать образ не нужно:

    ./update-image.sh   # или: sudo docker compose up -d --force-recreate onec-server

## Резервная копия

    ./backup.sh mybase [пользователь] [пароль]   # выгрузка в .dt в ./backups/dt
    ./backup.sh --cf mybase [пользователь] [пароль] # конфигурация в .cf в ./backups/cf
    ./backup.sh --pg mybase                      # дамп PostgreSQL (pg_dump -Fc) в ./backups

Выгрузку в .dt делает конфигуратор внутри контейнера сервера (компонент client_full,
виртуальный дисплей xvfb) — графическая сессия не нужна. Перед выгрузкой завершите
сеансы пользователей. Каталог задаётся BACKUP_DIR в .env.



## Импорт

    ./import.sh mybase file.dt dt Администратор 'пароль_1С'
    ./import.sh mybase file.cf cf Администратор 'пароль_1С'
    ./import.sh mybase file.dt dt Администратор 'пароль_1С' postgres 'пароль_PG'

Импорт выполняет утилита ibcmd из платформы (8.3.20+), конфигуратор и графический дисплей
не нужны. Подключение к СУБД по умолчанию берётся из .env (DB_NAME, DB_USER, DB_PASS —
пароль POSTGRES_PASSWORD), хост postgres, порт 5432. Последние два аргумента (и поля
«Пользователь PostgreSQL»/«Пароль PostgreSQL» в панели) переопределяют пользователя и пароль
СУБД; если не заданы — используются значения из .env.

Как выбирается способ:

- Пользователей 1С в базе нет (новая база: её создал start.sh или панель) — ibcmd
  аутентифицироваться не может, поэтому восстановление делает конфигуратор без логина.
  Наличие пользователей проверяется по представлению v8users, а не по числу таблиц
  (служебные таблицы 1С создаёт сразу при создании базы).
- Пользователи есть — сначала ibcmd (нужны пользователь 1С с правами администратора
  и его пароль), при отказе — конфигуратор с этими же учётными данными. ibcmd
  аутентифицируется в самой информационной базе, это не пользователь PostgreSQL;
  без логина он спрашивает «Имя пользователя» и падает с Invalid seek.

Эквивалент команды для базы с данными:

    /opt/1cv8/current/ibcmd infobase \
      --dbms=PostgreSQL \
      --db-server="postgres port=5432" \
      --db-name=mybase \
      --db-user=postgres \
      --db-pwd='…' \
      restore --force \
      --session-terminate-message="Идёт загрузка базы" \
      --user=Администратор --password='пароль_1С' \
      /home/usr1cv8/backups/dt/mybase.dt

Файл .dt должен лежать в BACKUP_DIR/dt, .cf — в BACKUP_DIR/cf (каталог BACKUP_DIR смонтирован в контейнер как /home/usr1cv8/backups). Старые файлы, оставленные непосредственно в BACKUP_DIR, также поддерживаются при импорте.

Для .cf выполняется ibcmd infobase config load и config apply --force --session-terminate=force.
Если платформа отказывает (для кластерной базы ibcmd infobase config может быть недоступен),
скрипт автоматически повторяет загрузку конфигуратором через 1c-xvfb — в консоли будет видно,
какой путь сработал.

## Память

Лимит памяти контейнера 1С задаётся SERVER_MEMORY_LIMIT в .env (например 8g, 512m;
0 — без лимита, по умолчанию). Его же можно менять из панели: вкладка «Контейнеры» →
«Память сервера 1С» — значение записывается в .env, контейнер пересоздаётся.
Это лимит Docker (страховка от OOM хоста), а не настройка рабочих процессов 1С: их память
ограничивается в кластере. PostgreSQL пока без лимита (shared_buffers = 256 МБ).

## Базовые образы

SERVER_BASE_IMAGE и POSTGRES_BASE_IMAGE в .env. Для postgres берите дистрибутив,
под который собраны ваши deb-пакеты 1С — иначе apt не сможет удовлетворить зависимости.
Определить по зависимостям пакета (dpkg-deb -f postgresql-*.deb Depends):

    libc6 >= 2.43, libicu78, libxml2-16   -> ubuntu:26.04
    libc6 >= 2.39, libicu74               -> ubuntu:24.04
    libc6 >= 2.35, libicu70               -> ubuntu:22.04

Сборка сама сверяет требуемую пакетами версию libc6 с образом и останавливается
с понятным сообщением, если база не та. Список apt-пакетов в Dockerfile сервера рассчитан на поддерживаемые базовые образы.

## Установка платформы (install-platform.sh)

Dockerfile сервера вызывает install-platform.sh: выбирает .deb или .run своей архитектуры
и версии, для setup-full*.run подбирает допустимые компоненты по справке установщика
и проверяет, что установился ragent. Нужен именно setup-full (setup-thin серверных
компонентов не содержит).
